## Permission UX requirements

The host agent reports its Screen Recording preflight and Accessibility trust states in `HostStatus` over the private local IPC channel. The Settings page displays those host-process values separately, explains missing permission, and shows Unknown if the host agent is unavailable or does not report the fields. `Open Settings` buttons are explicit user actions; there is no automatic prompt. The backend’s `request_screen_recording_access()` remains separate and is not called by app startup or passive checks.

The explicit buttons start the macOS `open` command with one of two fixed URLs: `x-apple.systempreferences:com.apple.preference.security?Privacy_ScreenCapture` or `x-apple.systempreferences:com.apple.preference.security?Privacy_Accessibility`. A unit test verifies the mapping from each permission to its distinct URL. Neither URL nor the resulting pane has been exercised on Monterey; verify this behavior on the Mac. The host may still log a missing pane, but app startup does not silently open System Settings.

## Key and cursor behavior decisions

USB HID keys remain physical-position identities. HID GUI maps to Command and HID Control maps to Control; cross-OS shortcuts retain the physical key and do not change semantic meaning. There is no automatic Ctrl/Command swap in this build. A future user preference may swap those two modifier positions without changing the default or transport representation. See ADR 0037.

For Mac-host capture, the pointer is baked into the video by both ScreenCaptureKit and CGDisplayStream. The foreground host sends a hidden-cursor datagram after each successful stream reset so the viewer does not render a second pointer. This follows the M9 prompt and ADR 0042; Windows keeps the separate cursor metadata path. Mac hardware must verify that both backends include the pointer.

## VideoToolbox details and limits

The encoder implementation requests hardware H.264 Main, real-time mode, no frame reordering, 30 fps, configured bitrate/data-rate limits, and a long keyframe interval. It first attempts the low-latency encoder specification, then retries hardware-only without that optional request. It rejects a session that does not report hardware acceleration. A requested keyframe is passed to VideoToolbox, and the output callback converts the sample to bounded Annex B with parameter-set handling. These are code paths, not Mac runtime evidence; this host's encoder target check is blocked by the OpenH264 C++ build dependency.

The decoder creates a VideoToolbox session from bounded SPS/PPS, requires hardware decode, requests video-range NV12, and returns bounded copied Y/UV planes. The app selects it on macOS and uploads planes through the shared wgpu shader. Strict macOS app-target Clippy passes from the Windows host, but Apple linking and runtime remain unverified. A direct IOSurface/Metal handoff is not implemented. Neither real encode/decode output, no-B-frame behavior, frame timing, nor upload cost has been measured.

No Mac capture, encoder, decoder, end-to-end, or thermal measurement exists. Keep the Mac-host default at **720p30** until sustained hardware testing supports raising it; the product ceiling remains 1080p30.

## LaunchAgent and local IPC design

The per-user host LaunchAgent template lives at `packaging/macos/com.racc.connect.host-agent.plist.in`; `scripts/install-launch-agents.sh` and `scripts/uninstall-launch-agents.sh` are human-run and have not been executed on the Mac. The host entry uses `KeepAlive` and launches only in the logged-in GUI session. Mutable state and the IPC socket live beneath `~/Library/Application Support/RaccConnect`; the socket directory is mode `0700`, socket mode `0600`, owner-checked, and the listener caps simultaneous workers. The app has a Unix-socket client. Hosting enable/disable still returns `Unavailable`: the host runtime lacks a safe reversible suspend/resume lifecycle and owner-loop command/reply path for stopping/reconstructing resources and safely rebinding. The separate remote control server now drains accepted handlers before stop returns, but that alone does not make the local hosting toggle safe. The machine-wide CPU sampler reads aggregate Mach host ticks once per StatsReport interval and reports unknown until a valid delta exists; three deterministic fake-counter tests pass, while Apple API behavior is unverified. The standard-library logger writes fixed lifecycle and permission messages and stays capped at 1 MiB; clipboard and input data are excluded. Sleep/wake, screen-lock, login behavior and file permissions remain human tests. ADR 0038 records the launch contract. Do not treat source integration as verified login hosting.

## Bindings and dependency boundary

The ScreenCaptureKit path uses the maintained `objc2` family and RAII wrappers. Objective-C/CoreGraphics calls are isolated in macOS-gated modules with SAFETY comments. Apple framework dependencies are target-gated to macOS; capture uses `objc2` 0.6.5, objc2 framework crates 0.3.2, `block2` 0.6.2, and `dispatch2` 0.3.1. The Windows capture dependency tree contains no objc2-family crates. ADR 0035 predates these bindings and must be reconciled; its earlier statement that no Apple binding dependencies were added is stale.
