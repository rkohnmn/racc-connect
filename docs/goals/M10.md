# Goal M10: polish and packaging (tray, autostart, installers, logo, license groundwork)

Save as `docs/goals/M10.md`.

**Run after:** M8 and M9 complete, with their human checks reviewed.
**Decisions only you can make first (edit this file before launching):**
1. **Project license.** Choose one, or leave "undecided" and the goal will prepare the comparison and the notices without adding a LICENSE file. Your repository is public; with no license, nobody else may legally reuse the code.
2. **Distribution scope:** personal use only on your three machines, or shared with others. Sharing means code signing matters (Windows SmartScreen warnings, macOS Gatekeeper and notarization).
3. **Apple Developer Program** membership (paid) if you want a notarized Mac build. Not needed for your own Mac.

Set these two lines before launching:

`CHOSEN LICENSE:` undecided
`DISTRIBUTION:` personal-only (assumed from docs/PROJECT_SCOPE.md; owner confirmation pending)

## Human checklist
1. Working tree clean on `main`; Windows and Mac builds both working.
2. For the installer build you will need the installer tooling named in the prompt installed on the Windows PC (the agent will not install it).
3. A clean test machine or VM for install and uninstall testing is strongly recommended.

## Launcher
```
/goal Complete the work specified in docs/goals/M10.md. Read AGENTS.md, docs/goals/COMMON.md, docs/DEV_SETUP.md and docs/PROGRESS.md first. Done only when every acceptance check in docs/goals/M10.md passes with evidence, then stop.
```

## Prompt
~~~text
GOAL: M10. Make Racc Connect installable and pleasant to live with: real system tray behavior, single-instance handling, persistent settings, autostart on both platforms, reproducible release builds, Windows installer and macOS app bundle packaging, firewall setup, third-party license notices, the raccoon logo and icons, a user guide, and the license preparation.

COMMON.md applies in full. Read AGENTS.md (sections 5, 10, 13, 14), docs/PROJECT_SCOPE.md, docs/UI.md, docs/HOST.md, docs/MACOS.md, docs/PACKAGING.md, docs/OPEN_QUESTIONS.md and docs/HARDWARE.md first. The values for CHOSEN LICENSE and DISTRIBUTION are in this goal file.

PREFLIGHT
Clean tree; check-all green on the machine you are on; M8 and M9 complete. Note which OS you are running on: Windows-only steps are skipped on macOS and vice versa, with the other machine's steps added to the human checklist.

DEPENDENCIES AND UNSAFE
tray-icon (or the toolkit's supported tray mechanism per ADR 0001) and a single-instance mechanism (a named mutex or lock file; no new crate if simple). Any asset tooling lives in tools/ outside the main workspace (its own Cargo.toml and lockfile) so main workspace dependency policy is unaffected; generated assets are committed with provenance. unsafe only in the existing platform modules.

SCOPE

1. Tray and window lifecycle. Replace the no-op TrayController with real implementations on Windows and macOS: icon, tooltip with connection state, menu (Open Racc Connect, Hosting on/off, Quit), left-click behavior documented; close button hides to tray and hosting continues (the host agent is separate); Quit stops the app only (the service or LaunchAgent keeps hosting unless the user turns hosting off). On macOS use a template (monochrome) menu bar image. Single instance: a second launch brings the existing window forward and exits. Window geometry restored on next launch (validated against current displays so it never opens off-screen). Test the pure parts (menu model, geometry validation) and record the platform behavior as VERIFIED-RUN where the agent ran it.

2. Settings persistence. A versioned settings file (JSON) in the per-user config folder: window geometry, sidebar states, default quality, capture release hotkey, clipboard toggle, hosting preference, key-swap setting (macOS Ctrl and Command), last device and display. Schema version and forward-compatible migration, atomic writes, corruption handling (move the bad file aside, start with defaults, show a notification), bounded size. No secrets, no identifiers beyond opaque device ids. Tests including migration and corruption.

3. Autostart. Windows: the host service already starts at boot (M6); add app autostart through the current user's Run registry key, toggled from Settings, with reversible writes and an uninstall cleanup path. macOS: a LaunchAgent for the app and the host agent per docs/MACOS.md, installed by the installer or by a Settings toggle (note that the newer login-item API is not available on macOS 12). Tests with a fake registry or filesystem; real behavior is HUMAN-PENDING.

4. Firewall. Windows Defender Firewall blocks inbound connections by default, including on the Tailscale interface. Provide scripts/firewall-rules.ps1 (human-run, elevated, with --dry-run and a matching removal script): an inbound rule for the host agent program allowing the control TCP port only from the Tailscale address range (100.64.0.0/10 and fd7a:115c:a1e0::/48), and an inbound rule for the app program allowing UDP from the same ranges (the viewer receives video on an ephemeral UDP port). The installer applies and removes these rules. macOS: document the application firewall prompt and the Tailscale interface behavior. Mark all verification HUMAN-PENDING and record any prompts the human saw during M6 and M7 testing in docs/PACKAGING.md.

5. Release builds. Release profile tuned by measurement (LTO, codegen units, strip; decide on panic strategy by checking behavior and size; record the numbers). scripts/build-release.ps1 and .sh produce versioned artifacts in an ignored dist/ folder with SHA-256 checksums. Version from the workspace version; CHANGELOG.md started. A panic hook that logs location and message (no user content) to the log folder. Record binary sizes and idle memory of the release agent and app.

6. Windows packaging. Choose and implement one installer approach that the human can build with a freely available tool (for example an Inno Setup script or a WiX project), plus a portable zip. The installer: installs the app and host binaries under Program Files, registers and starts the service (using the M6 install logic), applies the firewall rules, creates Start Menu shortcut, optional app autostart, and a clean uninstaller that stops and removes the service, firewall rules, autostart entries and (optionally, with a prompt) the data directory. Build and test steps are HUMAN-PENDING; the agent writes the scripts, validates their syntax where it can, and documents exactly how to build. Code signing: document the options and the user-facing consequences (SmartScreen) in docs/PACKAGING.md; do not attempt to sign.

7. macOS packaging. A script that builds the .app bundle (Info.plist with bundle id, usage descriptions, LSUIElement or Dock policy decision documented, icon), embeds the host agent, ad-hoc signs it for personal use, and prepares the notarization workflow (codesign with hardened runtime, notarytool submission, stapling, DMG via hdiutil) as documented scripts that require the human's Developer ID and credentials (the agent never handles credentials). Verify the bundle structure with codesign --verify where available; run on the Mac only.

8. Logo and icons. The logo is a raccoon emoji with a dark-theme blue-purple colorway (for example a rounded-square or circle badge in the app's accent color with the raccoon on it). Use openly licensed artwork only: verify the exact license of the Google Noto Emoji raccoon (U+1F99D) from its source repository's license files at the time of the run; do not use Apple's emoji artwork or any Discord logo shape or asset. If you can read the source and the license permits it, record the source URL, commit or version, license text location and your modifications in docs/ASSETS.md and include required attribution in the notices. If you cannot verify the license, do NOT use it: draw an original simple raccoon-face glyph as an SVG instead and mark the Noto option BLOCKED-HUMAN with instructions. Produce: SVG master, PNG sizes, Windows .ico, macOS .icns, a monochrome menu bar template icon, tray icons for connected and disconnected states. Use a small tools/icons generator (own workspace) and commit the outputs. No Discord name or imagery anywhere (repository search evidence).

9. Third-party notices. Generate THIRD_PARTY_LICENSES.md from the resolved dependency tree (cargo metadata plus license files where available) including the icon artwork attribution, include it in the installers and in the app's About page. Add scripts/gen-notices to the release scripts and a check that fails if a dependency lacks a recognized license. Keep the cargo-deny policy unchanged.

10. License preparation. If CHOSEN LICENSE names a license: add the LICENSE file(s), update README, Cargo.toml license fields and the notice generation, and record an ADR confirming compatibility with the dependency tree (run cargo deny licenses). If it is "undecided": write docs/LICENSE_OPTIONS.md comparing MIT, Apache-2.0, dual MIT OR Apache-2.0, GPL-3.0, AGPL-3.0 and proprietary for this project (public repository, goals of personal use or sharing, dependency compatibility, patent considerations including H.264 and the OpenH264 note, effect on the UI toolkit's license terms from ADR 0001) in plain language without legal advice claims, and do not add a LICENSE file. Say clearly that this is not legal advice.

11. User guide and README. docs/USER_GUIDE.md: install on each OS, first run, approving a peer, selecting a device and display, controlling and releasing capture, clipboard, quality, tray behavior, troubleshooting table (Tailscale not found, host not shown, black video, permission prompts on macOS, firewall prompts, stuck input), uninstall. Update README.md with status, screenshots of the real UI (synthetic or non-private content only), build and install instructions, supported platforms, limitations (no audio, no HDR, 1080p30 maximum, Windows lock screen and UAC caveats from the M6 results, Mac host limits from M9), and the license notice.

12. Final hardening pass (read-only review plus fixes with tests): review the public repository for secrets or personal data (hygiene script over history), review the allowlist, bind and local IPC rules once more against the code, check that logs contain no input, clipboard or frame content, confirm scripts/check-features still proves test-bind is absent from release binaries, and confirm no TODO or unimplemented! remains in non-test code paths (list any that remain with justification).

TESTS
Settings migration and corruption; geometry validation; tray menu model; autostart writers with fakes; notices generator (fixture tree); release script dry runs; hygiene and features checks; icon generator reproducibility (same inputs produce the same bytes where feasible); a check that the About page lists the generated notices.

DOCUMENTATION
docs/PACKAGING.md (final), docs/ASSETS.md, docs/USER_GUIDE.md, docs/LICENSE_OPTIONS.md (if undecided), CHANGELOG.md, updated README. ADRs: installer approach, tray approach, release profile decisions, logo asset choice, license decision. Update PROGRESS.md and OPEN_QUESTIONS.md. docs/HARDWARE.md human checks (HUMAN-PENDING): build the Windows installer, install on a clean machine or VM, observe SmartScreen and firewall behavior, confirm the service starts, the tray works, autostart works, firewall rules are scoped correctly (test that a non-Tailscale address cannot connect if you can), uninstall leaves nothing behind (service, rules, registry, files); on the Mac, build the bundle, run it ad-hoc signed, grant permissions, confirm the LaunchAgent starts at login, test the notarization workflow if you have a Developer ID; both platforms: leave it running for 24 hours and record CPU, memory and any leak; update from one version to the next without losing settings or the allowlist.

HARD CONSTRAINTS
Never handle signing credentials. Never run installers, firewall scripts, service or LaunchAgent installs yourself. Never use Apple emoji artwork or Discord assets. Do not choose a license unless CHOSEN LICENSE names one. Do not add features beyond this scope.

ACCEPTANCE CHECKS
B1 to B8, plus:
P1. Tray, single-instance, settings and autostart logic tests pass; platform behavior observed on the OS the agent ran on is recorded with labels.
P2. Release scripts run in dry-run and real build modes on the agent's OS and produce checksummed artifacts; sizes and idle memory recorded.
P3. Installer and bundle scripts exist and are documented; all install, firewall and signing steps are HUMAN-PENDING with exact instructions.
P4. docs/ASSETS.md records the logo source, license verification and modifications (or the original-art fallback and BLOCKED-HUMAN note); icons exist in all required formats.
P5. THIRD_PARTY_LICENSES.md is generated and the check for unrecognized licenses works.
P6. License handling matches CHOSEN LICENSE as specified; no legal-advice claims.
P7. USER_GUIDE.md, README, CHANGELOG and docs are updated; hygiene and features checks pass; the hardening review is reported.

FINAL REPORT: COMMON.md section 14, plus the artifact list with sizes and checksums, the license and asset status, and the complete list of human steps remaining before a first release.
~~~
