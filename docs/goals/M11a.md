# Goal M11a: pop-out windows, part 1 (multi-stream protocol, session logic, window geometry)

Save as `docs/goals/M11a.md`.

**The feature (all three M11 goals):** pick one application window from a list on a remote computer and pop it out as its own local window with the same title and size as on the remote machine, scalable with the aspect ratio locked. It works independently of the main window: closing the main window to the tray leaves the pop-out running, with a way to reopen the main window. Only one pop-out at a time. Windows 10 is the priority platform.

**Run after:** M8 and M10 complete (the protocol and tray work must be settled first).
**Revisit before running:** read the final `docs/PROTOCOL.md` (M8 may have bumped the version and added messages) and `docs/SESSION.md`. If field names or the version number changed, adjust the wire section below first.

~~~text
GOAL: M11a. Add multi-stream support and window-stream logic without any OS code: the wire protocol changes (stream ids and window messages), per-stream transport in racc-net, the sans-IO window-stream state machines in racc-session, the bitrate allocation policy, and the pure window geometry and pointer math in racc-topology. Everything is deterministic and testable here.

COMMON.md applies in full. Read AGENTS.md (sections 4, 7, 8), docs/PROTOCOL.md, docs/TRANSPORT.md, docs/SESSION.md, docs/TOPOLOGY.md, docs/TELEMETRY.md and ADR 0016 first.

PREFLIGHT
Clean tree; check-all green; M8 and M10 complete. Confirm the current PROTOCOL_VERSION and message list from docs/PROTOCOL.md and use the next free message type numbers and version.

FIXED PRODUCT RULES
- Exactly two stream slots: stream 0 is the display stream (existing behavior), stream 1 is the single window stream. At most ONE window stream at a time, regardless of platform. Opening another while one is open is rejected by the host with Busy; replacing is an explicit close then open done by the viewer. MAX_STREAMS = 2 is a named constant.
- Window streams are windows-only on the host in this feature (macOS hosts will not advertise the capability).
- Input to a window may cause the host to raise that window (decided later, in M11b); this goal only carries the messages and validation.

PART 1. PROTOCOL (racc-proto), bump PROTOCOL_VERSION, update golden vectors and docs/PROTOCOL.md in the same commit
1. Video and cursor datagram headers: the reserved byte becomes stream_id (u8; valid values 0 and 1; anything else is InvalidValue). Header length stays 18. Update the validation tests (the old rule that reserved must be zero is replaced).
2. Add stream_id (u8) to PauseVideo, ResumeVideo, RequestKeyframe, StatsReport and InputEvent. In InputEvent the existing display_id field becomes target_id: a display id for stream 0, a window id for stream 1; validation of the pair is by the layer that knows the stream.
3. Capability: features bit 1 = WindowStreams in Hello and HelloAck (update the reserved-bit validation).
4. New messages (assign the next free type numbers, strict bounded parsing, closed enums, no trailing bytes):
   - SubscribeWindows {enable u8 (0 or 1)} viewer to host: start or stop receiving window lists.
   - WindowList host to viewer: rev u32, count u8 (at most MAX_WINDOWS = 64), then entries. WindowEntry: window_id u32 (nonzero), title string (at most MAX_NAME_BYTES, truncated at a UTF-8 boundary by the sender), app_name string (at most 64 bytes, executable base name only, no path, no process id), flags u16 (bit0 minimized, bit1 maximized, bit2 foreground, bit3 resizable, bit4 has_icon, bit5 protected_or_unknown), x i32, y i32, width u32, height u32 (visible frame bounds in host physical pixels in virtual-desktop space; width and height nonzero), display_id u32, scale_milli u16. Entries sorted by z-order, topmost first. Duplicate window ids are an error.
   - WindowIconRequest {window_id u32} and WindowIcon {window_id u32, width u16, height u16 (each 1..=64), BGRA bytes with exact checked length at most 16384}.
   - OpenWindowStream {req_id u32, window_id u32, mode u8 (1 Window, 2 Region), max_height u16 (0 Auto)} viewer to host.
   - WindowStreamReset {req_id u32 (0 if host-initiated), stream_id u8 (1), epoch u16, window_id u32, mode u8, codec u8, width u16, height u16 (encoded size), content_w u16, content_h u16 (the real content rectangle inside the encoded frame; content_w and content_h are at most width and height; used when small windows are padded), fps u8, status u8} where status is 0 Ok, 1 WindowNotFound, 2 Minimized, 3 Protected, 4 CaptureFailed, 5 EncoderFailed, 6 Busy, 7 Unsupported, 8 Closed.
   - WindowUpdate host to viewer: window_id u32, changed u8 bitmask (title, bounds, flags), then the same fields as a WindowEntry (so the viewer can retitle, resize and update input mapping). Sent at most 10 times per second per window.
   - CloseWindowStream {stream_id u8 (1)}.
   Document byte layouts, enums and validation in docs/PROTOCOL.md; add golden vectors for every new or changed message and both datagram headers; round-trip, truncation, trailing-byte and malformed tests; proptest including a 10000-case run. No new dependencies.

PART 2. TRANSPORT (racc-net)
1. Per-stream state in the sender: independent frame ids, epochs, send queues and pacing per stream_id over one shared UDP socket (threads and the socket may be shared; a single pacer thread per stream or one scheduler is your choice, document it). Backpressure signals and counters are per stream.
2. Receiver demultiplexes by stream_id into independent reassemblers with their own epoch, need_keyframe state, keyframe-request backoff, in-flight caps and counters. Events carry stream_id. Datagrams with an invalid or inactive stream id are counted and dropped. Memory budget is per stream (document the total).
3. If a recovery mechanism was added in M2.6, make it stream-aware (retention rings per stream within the global 2 MiB cap).
4. Tests: two concurrent streams through the impairment simulator and the loopback proxy: loss on one does not stall or corrupt the other; gap safety and bounded memory hold per stream; a hostile peer cannot exceed the combined budget; stream 1 inactive drops cleanly.

PART 3. SESSION LOGIC (racc-session, sans-IO, no new dependencies)
1. Window-stream state machines composed into ViewerSession and HostSession: states Closed, Opening, Streaming, Resetting, Paused, Closing. Constants: WINDOW_RESIZE_DEBOUNCE_MS = 250 (a window resize storm causes at most one host-initiated reset per 250 ms; during a storm the host keeps the current encoded size and the viewer keeps the current epoch), WINDOW_LIST_MAX_RATE_HZ = 1 (list pushes while subscribed and changed), WINDOW_UPDATE_MAX_RATE_HZ = 10, reuse the timeouts from M3b for open (SWITCH_TIMEOUT_MS) and first keyframe.
2. Behavior: open flow (OpenWindowStream, WindowStreamReset Ok, reset the stream-1 reassembler and decoder, wait for the first keyframe, then atomic replace as in display switching); Busy handling; replace helper (close then open) on the viewer; host-initiated resets on resize, mode change and window return from minimized; WindowStreamReset(status Minimized) pauses the stream and the viewer keeps the last frame with an overlay notification; restore resumes with a new epoch and keyframe; status Closed when the window is destroyed (the stream ends, the viewer is notified); Protected and CaptureFailed end or retry per M3b recovery rules (define and test); per-stream epochs with the same strict-newer rule as display streams.
3. Per-stream visibility: the viewer's visibility input becomes per stream (SetStreamVisible(stream_id, bool)). PauseVideo and ResumeVideo are stream-scoped. The control connection and heartbeat continue when all streams are hidden. The host releases capture and encode resources for a paused stream (Actions) and re-creates them on resume with a keyframe.
4. Input: for stream 1 the host validates stream_id, window_id (target_id) and epoch for pointer-absolute events, and keeps the pressed-key tracking and stuck-key release on stream close, pause, control loss and Closed. The viewer suppresses pointer input during Resetting as it does during display switching.
5. Reconnect: after control loss and reconnect, the viewer re-subscribes and re-requests the same window stream (match by window_id first; if the host restarted and ids changed, match once by app_name plus title; otherwise notify that the window is no longer available). The pop-out is not torn down by the session layer; the UI decides.
6. Aggregate bitrate allocation: a pure function allocate_bitrate(streams, host_budget_kbps, policy) used by the host runtime. Policy: the window stream has priority; when both streams are active and the sum of requested bitrates exceeds the host budget (default 12000 kbps; macOS hosts default 6000 via host_caps), reduce the display stream first (bitrate within its tier down to 70 percent, then one tier down), then the window stream within its range; never below the 480p-equivalent floor for the display stream or below 500 kbps for the window stream; recompute when streams open, close or pause. Property tests for monotonicity and caps.
7. choose_window_stream_params(window_bounds, scale_milli, quality_pref, host_caps) pure function: encode at the window's pixel size without upscaling, even dimensions, never exceeding the tier box (480: 854x480, 720: 1280x720, 1080 and Auto: 1920x1080) by scaling down while preserving aspect ratio; the 480p minimum tier applies to display streams only, so small windows stream at native size; minimum encoded size 128x128 with the content placed at the top-left and padded, reporting content_w and content_h; fps 30; bitrate scaled by pixel area from the tier defaults with a floor of 500 kbps. Table tests: tiny 300x200, 640x480, 1366x768 window, maximized 1920x1080 and 3840x2160 windows, tall 400x1400, ultrawide 2560x600, odd sizes.

PART 4. WINDOW GEOMETRY AND POINTER MATH (racc-topology, new module window, pure, unsafe-free, i64 or u64 intermediates)
1. Pop-out initial size: given the remote window's visible bounds and scale_milli, the local display work area (size and scale_milli) and the local frame chrome sizes (title bar and borders in pixels supplied by the caller), compute the initial client size in local physical pixels so the window appears the same logical size as on the host (remote physical divided by remote scale, multiplied by local scale), clamped to fit inside the local work area (shrink preserving aspect) and to a minimum and maximum scale of 25 percent and 400 percent of the remote size. Also a 1:1 physical-pixel option.
2. Aspect-locked resize solver: given the current client size, aspect ratio (from the content rect), the user's proposed outer size, the dragged edge or corner, chrome deltas, and size limits, return the constrained outer size so the client area preserves the aspect ratio within one pixel; consistent with how Windows WM_SIZING reports edges (document the edge enumeration). Properties: output within limits, aspect error at most one pixel, idempotent, monotonic in the dragged dimension.
3. Scale helpers: current scale factor as a rational of client size over content size, snapping to 100 percent and Fit, step zoom in and out.
4. Window pointer math: viewer (px, py) within the rendered video rectangle to fixed-point (u, v) over the CONTENT rectangle (not the padded frame); host screen position X = bounds.x + round_half_up(u * (bounds.width - 1) / 65535) and Y likewise, clamped inside bounds; letterboxing uses the content rect aspect; the cursor overlay mapping for window streams (cursor position given relative to the window's top-left).
5. Table-driven tests including mixed DPI (remote 150 percent, local 100 percent and the reverse), negative origins, windows near screen edges, padded tiny windows, huge windows downscaled by the encoder, a 25 percent scale, resize edge cases, and property tests (10000 cases once).
~~~
