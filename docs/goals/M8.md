## Prompt
~~~text
GOAL: M8. Add text clipboard sync between machines, wire all live telemetry into the UI sidebar, and implement the host quality controller that adapts resolution and bitrate to loss and delay within the 480p30 to 1080p30 range.

COMMON.md applies in full. Read AGENTS.md (sections 4.3, 5.1, 7, 8), docs/SESSION.md, docs/TELEMETRY.md, docs/TRANSPORT.md, docs/TRANSPORT_AUDIT.md, docs/VIEWER.md, docs/HOST.md and docs/UI.md first.

PREFLIGHT
Clean tree; check-all green; M7 complete; read the M7 human results.

DEPENDENCIES AND UNSAFE
windows crate features for clipboard (clipboard format listener window, CF_UNICODETEXT) and system times (host CPU usage) inside crates/clipboard/src/windows/ and the host's system-metrics module. A small crate such as clipboard-win is acceptable only if it is permissively licensed and reduces unsafe code; justify in an ADR. unsafe confined to those modules with SAFETY comments.

PART 1. CLIPBOARD (crates/clipboard, package racc-clipboard)
1. Portable core (pure, sans-IO): ClipboardSync state machine handling local changes and remote ClipboardUpdate messages with loop prevention (every update carries origin and seq; remember the hash and seq of the last applied remote value and ignore the echo when the local clipboard listener reports that same change; monotonically increasing seq per sender; bounded memory), size limits (MAX_CLIPBOARD_BYTES 512 KiB, reject larger and show a notification), UTF-8 validation, rate limit (for example at most 5 updates per second, coalescing bursts, latest wins), and enable/disable per direction and per session with a user-visible setting. Clipboard sync is on only while a session is Active and the user has clipboard enabled; pending data is dropped at session end. Never log clipboard contents.
2. Windows backend: a message-only window with AddClipboardFormatListener to receive change notifications (no polling); read CF_UNICODETEXT with retry on contention (the clipboard may be held by another process; bounded retries with backoff); write remote text and suppress the resulting local notification; handle apps that delay-render; ignore non-text formats; convert line endings consistently (document the rule). Runs in the same session as the user who owns the clipboard: in the service model this is the helper on the host side and the app on the viewer side; make sure host-side clipboard access works from the console-session helper. If the secure desktop or lock screen blocks access, report a status.
3. Wire up: the session layer or core forwards ClipboardUpdate both directions; the UI shows a small clipboard status (last sync time, direction, rejected-too-large notices) in the CONTROL > Clipboard page and a toggle.
4. Tests: loop prevention (A to B to A echo), simultaneous changes on both sides (deterministic tie rule documented), size limit, burst coalescing, invalid UTF-8, seq wraparound, disable and enable, session end clearing, fake backend contention retries; a real round trip on this PC between a fake remote and the real Windows clipboard (VERIFIED-RUN, using a test string that is not private and restoring nothing sensitive).

PART 2. TELEMETRY WIRING
1. Populate every field in the SESSION, HOST and EVENTS sections of the sidebar from real sources: RTT from Ping/Pong (racc-telemetry), packet loss and frame loss from the reassembler's estimator, bitrate and FPS from rolling windows over received data and delivered frames, codec, decoder name, connection state, path kind (Direct, Derp or Unknown from racc-identity status), epoch; host CPU percent (host process or machine? decide and document; use the machine-wide figure with the process figure as a secondary value), capture backend, encoder, resolution, display refresh, target and actual bitrate via StatsReport sent by the host once per second.
2. The core publishes immutable snapshots to the UI at about 4 Hz; the UI never blocks video threads and does not rebuild its tree per update. Events (display switch, decoder reset, connection established, quality adjustment, packet loss event, capture lost, encoder fallback, paused and resumed) appear in the EVENTS list with timestamps.
3. Verify with a test that sidebar updates do not change video frame pacing: record frame interval p95 with the sidebar updating versus not (VERIFIED-RUN on this PC, loopback).

PART 3. QUALITY CONTROLLER (in racc-session as a pure module, used by HostRuntime)
1. Inputs: loss fraction and frame-loss fraction (viewer reports them to the host in StatsReport-like feedback: if the wire lacks a field for viewer-to-host loss feedback, add a small control message `ViewerReport {epoch, loss_permille, frame_loss_permille, rtt_ms, decode_ms_p95, dropped_frames}` sent once per second, bump PROTOCOL_VERSION and follow the wire-change rules), RTT, sender queue drops, encoder lag, and the user's quality preference (Auto or a fixed tier) and the host's max tier.
2. Behavior for Auto (starting policy; tune from data and record changes in an ADR): step down one tier after 3 consecutive seconds with loss above 2% or frame loss above 5% or RTT above 3 times its baseline minimum for 5 seconds; step down immediately when the sender queue overflows twice in 2 seconds; step up one tier only after 20 consecutive stable seconds (loss below 0.5%, RTT within 1.5 times baseline) and at most once per 30 seconds; never above the host maximum or the display height; never below 480p; within a tier adjust bitrate between 70% and 100% of the tier default before changing tier. Every change emits a QualityAdjustment event and, when the resolution changes, a host-initiated StreamReset via the existing switch path. A fixed tier preference disables stepping but still allows bitrate trimming within the tier.
3. Tests on the virtual clock: no oscillation under steady marginal loss (hysteresis), correct step down and up timing, caps and floors, preference handling, behavior across switches and resets, property tests that tier changes never exceed the rate limits.

DOCUMENTATION
docs/CLIPBOARD.md, update docs/TELEMETRY.md (final field sources), docs/SESSION.md (quality controller) and docs/PROTOCOL.md for any wire change. ADRs: clipboard conflict and loop rules, adaptation policy and thresholds, ViewerReport if added. docs/HARDWARE.md human checks (HUMAN-PENDING): clipboard in both directions between the two PCs with a large paste, repeated copies, copy in a locked or elevated app (document behavior), and non-ASCII text; adaptation under real conditions using a bandwidth limiter or Wi-Fi vs wired and watch tier changes, stability and the Events list; confirm the telemetry fields look right against reality (compare RTT to `tailscale ping`).
~~~
