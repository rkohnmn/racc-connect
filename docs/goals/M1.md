DESIGN DECISIONS (fixed; implement these; document them)

General
- All integers little-endian. PROTOCOL_VERSION is a u8 constant, value 0 (draft).
- Public constants in racc-proto, each documented and covered by tests: PROTOCOL_VERSION, MAX_DATAGRAM = 1200, VIDEO_HEADER_LEN = 18, MAX_VIDEO_PAYLOAD = 1182, MAX_FRAGMENTS_PER_FRAME = 1024, MAX_CONTROL_FRAME_BYTES = 1_048_576 (1 MiB, payload after the length prefix), MAX_CLIPBOARD_BYTES = 524_288 (512 KiB), MAX_DISPLAYS = 16, MAX_NAME_BYTES = 128 (display and device names, UTF-8), MAX_CURSOR_DIM = 128, MAX_CURSOR_BYTES = 65_536. Add compile-time assertions that MAX_VIDEO_PAYLOAD = MAX_DATAGRAM minus VIDEO_HEADER_LEN.
- Strings are length-prefixed UTF-8: u8 length then bytes, length at most MAX_NAME_BYTES, validated as UTF-8; invalid UTF-8 is an error, never lossy-converted.
- Decoders return typed errors (a ProtoError enum with distinct variants such as Truncated, TooLarge, InvalidValue, UnknownKind, UnsupportedVersion, InvalidUtf8, TrailingBytes). Decoders for control messages must reject trailing bytes inside a frame. Unknown message types are an error, not a panic or a skip.

Video datagram (UDP), kind 1 = video slice
- Header, 18 bytes exactly: version u8, kind u8, flags u8, reserved u8 (must be zero on send; nonzero is an error on receive), epoch u16, frame_id u32, frag_idx u16, frag_cnt u16, capture_ts_us u32.
- flags: bit0 KEY, bit1 LAST_FRAGMENT, bit2 CONFIG (SPS/PPS present in this frame). Unknown flag bits are an error.
- Validation: frag_cnt >= 1 and <= MAX_FRAGMENTS_PER_FRAME; frag_idx < frag_cnt; LAST_FRAGMENT set if and only if frag_idx == frag_cnt - 1; total datagram length <= MAX_DATAGRAM; payload length >= 1.
- The payload is a fragment of one H.264 access unit in Annex B format. A frame is the concatenation of its fragments in frag_idx order. The header parser must be allocation-free: it returns a small Copy struct and a borrowed payload slice.
- Session binding: video datagrams carry no session id. The host sends video to the viewer's IP and the video_udp_port the viewer announced in Hello; the receiver accepts datagrams only from the host address of its control connection. Document this in PROTOCOL.md.

Cursor datagram (UDP), kind 2 = cursor update
- Same first four header-like bytes (version, kind, flags=0, reserved=0), then epoch u16, then body: shape_id u32, x i32, y i32, visible u8 (0 or 1 only). x and y are host physical pixels relative to the top-left of the currently streamed display; the viewer applies the hotspot and scales. Fixed length. Define the exact byte layout in PROTOCOL.md and golden-test it.
- Cursor shape bitmaps are NOT sent by datagram (too large). They use the control message CursorShape below.

Control channel (TCP)
- Frame: u32 length (counts the type byte plus payload; must be >= 1 and <= MAX_CONTROL_FRAME_BYTES), then u8 message type, then payload. Provide an incremental frame decoder that can be fed arbitrary byte chunks (including one byte at a time) and yields complete frames, never allocating beyond MAX_CONTROL_FRAME_BYTES, and rejecting an oversize length immediately without reading the body.
- Messages (names fixed; type numbers assigned in the order below starting at 1, documented in a table). Field lists below are the v0 definitions:
  1. Hello (viewer to host): protocol_version u8, device_name string, os u8 (1 Windows, 2 macOS, 3 Linux, 0 Unknown), app_version string, video_udp_port u16, codecs u32 bitmask (bit0 H264), max_height u16, features u32 bitmask (bit0 ClipboardText).
  2. HelloAck (host to viewer): protocol_version u8, status u8 (0 Ok, 1 UnsupportedVersion, 2 NotAuthorized, 3 Busy), device_name string, os u8, app_version string, codecs u32, max_height u16, features u32, host_cpu_cores u8.
  3. TopologyAnnounce: topology_rev u32, active_display_id u32 (0 if none), then count u8 (<= MAX_DISPLAYS) of displays. Each display: display_id u32, name string, x i32, y i32, width_px u32, height_px u32, scale_milli u16, refresh_mhz u32, flags u8 (bit0 primary, bit1 active, bit2 available, bit3 hdr read-only label). display_id values within one message must be unique (duplicates are an error); width_px and height_px must be nonzero.
  4. SwitchMonitor (viewer to host): req_id u32, display_id u32.
  5. StreamReset (host to viewer): req_id u32 (0 if host-initiated), epoch u16, codec u8 (1 H264), width u16, height u16, fps u8, topology_rev u32, display_id u32, status u8 (0 Ok, 1 DisplayNotFound, 2 CaptureFailed, 3 EncoderFailed, 4 Paused, 5 Busy). width and height must be nonzero and fps nonzero when status is Ok.
  6. SetQuality (viewer to host): max_height u16 (0 means Auto), bitrate_hint_kbps u32 (0 means Auto). Non-zero max_height must be one of 480, 720, 1080 (v0 tiers); anything else is InvalidValue.
  7. RequestKeyframe: epoch u16.
  8. PauseVideo: no fields. 9. ResumeVideo: no fields.
  10. InputEvent (viewer to host): epoch u16, display_id u32, then a tagged event: tag 1 MouseMoveAbs {u u16, v u16 (0..=65535 fixed-point fraction of the rendered video rectangle)}, tag 2 MouseMoveRel {dx i16, dy i16}, tag 3 MouseButton {button u8 (1 left, 2 right, 3 middle, 4 back, 5 forward), pressed u8 (0 or 1)}, tag 4 Wheel {dx i16, dy i16 in 1/120 notch units}, tag 5 Key {hid_usage u16 (USB HID usage page 0x07), pressed u8 (0 or 1), modifiers u8 (bit0 shift, bit1 ctrl, bit2 alt, bit3 meta)}. Using USB HID usage codes as the cross-platform key identity is a deliberate decision (Windows and macOS both map to and from it). Unicode text injection for international layouts is deferred; record that as an open question.
  11. ClipboardUpdate: seq u32, origin u8 (0 viewer, 1 host), kind u8 (1 = UTF-8 text), then u32 length (<= MAX_CLIPBOARD_BYTES) and bytes; text must be valid UTF-8. Other kinds are rejected in v0.
  12. StatsReport (host to viewer): host_cpu_pct_x10 u16 (0..=1000), capture_backend u8 (0 Unknown, 1 DXGI, 2 WGC, 3 ScreenCaptureKit, 4 CGDisplayStream), encoder u8 (0 Unknown, 1 MediaFoundationHw, 2 OpenH264, 3 VideoToolbox, 4 Nvenc, 5 Amf, 6 Qsv), width u16, height u16, display_refresh_mhz u32, target_bitrate_kbps u32, actual_bitrate_kbps u32.
  13. Ping: nonce u64, sender_ts_us u64. 14. Pong: nonce u64, echo_ts_us u64 (used for RTT telemetry).
  15. CursorShape: shape_id u32, width u16, height u16 (each 1..=MAX_CURSOR_DIM), hotspot_x u16, hotspot_y u16 (each less than the corresponding dimension), then BGRA pixel bytes whose length must equal width times height times 4 and must not exceed MAX_CURSOR_BYTES (check with overflow-safe arithmetic).
  16. Goodbye: reason u8 (0 Normal, 1 Error, 2 Superseded, 3 NotAuthorized, 4 Shutdown).
- Unknown enum values in fields where this list defines a closed set are InvalidValue errors. Reserved bits in bitmasks that are not defined here are InvalidValue errors.
- These two messages are additions to the AGENTS.md list: Ping, Pong and CursorShape. Record them in an ADR (0009) with the reasons: RTT telemetry and cursor-shape transport.

API shape (you choose names; satisfy these properties)
- Every message type has encode into a caller-provided growable buffer (no hidden global state) and decode from a byte slice that returns the value and bytes consumed or a ProtoError.
- A top-level ControlMessage enum covers all 16 messages with encode_frame (adds length and type) and a decode path from a complete frame body.
- Video: encode of header plus payload into a buffer, and parse of a datagram into (header, payload slice), allocation-free.
- Types are plain data: Clone, Debug, PartialEq, Eq where possible. No lifetimes on control messages (owned strings and vectors) is acceptable; the video path must borrow.
- Public API documented with doc comments; cargo doc must produce no warnings.

8. proptest: (a) generated valid messages round-trip; (b) arbitrary byte vectors up to a few KiB never panic any decoder (video, cursor, control frame, each message decoder, incremental decoder); (c) arbitrary mutated valid encodings (bit flips, truncations, insertions) never panic.
