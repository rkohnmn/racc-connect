Implement the transport layer in crates/net (package racc-net) and the network impairment tools in crates/testkit (package racc-testkit): UDP frame slicing, reassembly with latest-wins and gap-safety, keyframe-request policy, sender pacing and send-queue backpressure, TCP control connection I/O, and bind-address policy. DESIGN DECISIONS (fixed; implement and document them)

D1. Sans-IO core plus thin I/O shells.
- All transport logic (slicer, reassembler, pacer, send queue, keyframe-request policy, loss estimator, bind policy) is pure, deterministic and independent of sockets, threads and wall clocks. Time is an injected value: the caller passes now as microseconds on a monotonic timeline (a plain u64 newtype or similar), never calling Instant::now inside the core.
- Thin I/O modules wrap the core with real sockets and threads. They contain no policy.

D2. No async runtime in racc-net. Use std::net plus the socket2 crate (for buffer sizes and keepalive) and std threads. Allowed runtime dependency for racc-net: socket2 only (and racc-proto as a path dependency). Allowed dev-dependencies: proptest. racc-testkit may depend on racc-net and racc-proto. NO rand crate: implement a small deterministic seeded PRNG (xorshift64* or similar) in racc-testkit. Record in an ADR. racc-net keeps #![forbid(unsafe_code)] and racc-testkit must not use unsafe either.

D3. Uniform fragmentation rule (resolves open question 13). A frame of N bytes is split into ceil(N / MAX_VIDEO_PAYLOAD) fragments; every fragment except the last carries exactly MAX_VIDEO_PAYLOAD (1182) bytes; the last carries 1..=1182 bytes. N must be 1..=MAX_FRAGMENTS_PER_FRAME * 1182. The receiver enforces this: a non-last fragment of the wrong size, or a last fragment of 0 bytes, causes the whole frame to be dropped and counted. Because of this rule the receiver can place each fragment at offset frag_idx * 1182 and knows the exact frame size on completion. Amend docs/PROTOCOL.md (section on video slices) to state the rule and note: "v0 is an undeployed draft, so this clarification is made in place without a version bump." Update open question 13 as resolved. Also add to PROTOCOL.md that UDP datagrams preserve boundaries and WireGuard authenticates them, so payload truncation in transit is not a threat model concern.

D4. Per-frame consistency. KEY and CONFIG flag bits, capture_ts_us and frag_cnt must be identical across all fragments of one (epoch, frame_id). Any disagreement drops that frame and counts it. LAST_FRAGMENT is already validated by racc-proto.

D5. Reassembler policy (latest-wins plus gap safety). Implement exactly this behavior:
- Inputs: raw datagram bytes plus now. Parse with racc-proto (borrowed, allocation-free). Malformed datagrams are counted and dropped, never panic.
- Epoch: the reassembler has a current epoch set by the caller (from StreamReset). Datagrams from other epochs are counted and dropped. A reset(epoch) call clears all in-flight state, clears last-delivered, and sets need_keyframe = true.
- Serial arithmetic for frame_id (u32 wraparound, half-range window). A frame at or before the last delivered frame_id is a late drop. Duplicate fragments are ignored and counted.
- In-flight bounds: at most MAX_INFLIGHT_FRAMES = 4 partial frames and a total in-flight byte budget of 4 MiB (configurable). Fragment storage must be allocated lazily and bounded so a hostile peer declaring frag_cnt = 1024 on many frame ids cannot exceed the budget. When over budget or over the frame cap, evict the oldest frame_id first (and count it).
- Timeout: a partial frame that has received no new fragment for REASSEMBLY_TIMEOUT_MS = 100 is evicted and counted as dropped-incomplete.
- Delivery order: frames are delivered in increasing frame_id order, once, never out of order.
- Reorder window: REORDER_WINDOW_MS = 8. When a frame M completes while an older frame N is still incomplete, N is declared lost only if no fragment of N has arrived within the last REORDER_WINDOW_MS; otherwise M is held until the window expires (the caller's periodic poll(now) resolves it). When N is declared lost, M is NOT delivered unless M is a keyframe.
- Whole-frame loss: if a completing frame M has frame_id != last_delivered + 1 and no older partial frames explain the gap, the missing frames are lost and the same rule applies (M delivered only if keyframe).
- need_keyframe: initially true. While true, completed non-key frames are discarded (counted as dropped-waiting-for-key). A delivered KEY frame sets need_keyframe = false and drops all older in-flight state. Any loss declaration sets need_keyframe = true.
- Keyframe request policy: when need_keyframe becomes true, emit a NeedKeyframe event immediately; while it stays true, re-emit with backoff: minimum interval KEYFRAME_REQUEST_MIN_INTERVAL_MS = 200, doubling on each unanswered request up to KEYFRAME_REQUEST_MAX_BACKOFF_MS = 1000; backoff resets when a keyframe is delivered. Never more than one event per minimum interval. The event carries the current epoch so the caller can send racc-proto's RequestKeyframe message.
- Output events: FrameReady (frame bytes, frame_id, key flag, config flag, capture_ts_us), NeedKeyframe, and per-drop reasons through counters. A completed frame is returned as an owned Vec<u8> (per-frame allocation is acceptable in v0; buffer pooling is a later optimization; record this in the ADR).
- Counters (a plain struct, cheap to copy): datagrams_received, bytes_received, parse_errors, wrong_epoch, duplicates, late, frames_completed, frames_delivered, dropped_incomplete, dropped_waiting_key, dropped_inconsistent, dropped_evicted, keyframe_requests, current_inflight_frames, current_inflight_bytes.
- A rolling loss estimator over a configurable window (default 2 s): estimated packet loss fraction = missing fragments (for frames whose fragment count is known, from partial or dropped frames) divided by expected fragments. Exposed for later telemetry and adaptation. Whole-frame losses with unknown size count as a frame-loss rate instead; expose both numbers.

D6. Sender policy.
- Slicer: given frame bytes, epoch, frame_id, flags (KEY, CONFIG) and capture_ts_us, produce datagrams written into caller-provided buffers (no per-datagram allocation). Datagram size never exceeds MAX_DATAGRAM.
- Pacer: given the number of datagrams in a frame, the frame interval (default 33_333 us) and PACING_FRACTION_PERCENT = 60, compute send times so all datagrams of a frame leave within at most 60% of the frame interval, evenly spread, starting no earlier than now. Keyframes follow the same rule. The pacer must handle a frame arriving while the previous frame is still being sent (continuing the schedule, never sending faster than the spread).
- Send queue and backpressure: at most SEND_QUEUE_MAX_FRAMES = 2 frames waiting. If a new frame arrives and the queue is full, drop the oldest frame that has not started sending (never abandon a frame mid-send silently), count it, and raise a ForceKeyframe signal to the caller (the encoder will need an IDR because references were dropped).
- Sleeping: the real sender loop uses std::thread::sleep through an injectable Sleeper trait. Do not busy-spin. (No unsafe or platform timer calls in racc-net.)

D7. Control connection (TCP).
- Provide listener and connect helpers returning a ControlConn with: TCP_NODELAY set, SO_KEEPALIVE enabled (idle about 10 s), a configurable write timeout (default 2 s) and read timeout, send(&ControlMessage) (encode_frame from racc-proto), and recv() -> Result<ControlMessage, ...> using racc-proto's incremental FrameDecoder with its bounds. A way to split into independent read and write halves for use from separate threads (try_clone is acceptable).
- Errors are a typed enum (Io, Proto, Timeout, Closed, and so on). No panics, no unwrap on network input.
- Heartbeat (Ping/Pong) policy belongs to the session layer in M3, not here.

D8. Bind policy (security rule from AGENTS.md section 4.1).
- Pure function validate_bind_addr(addr, policy). Production policy Tailscale accepts only IPv4 addresses in 100.64.0.0/10 and IPv6 addresses in fd7a:115c:a1e0::/48, and rejects unspecified (0.0.0.0, ::), loopback, link-local, private LAN ranges and everything else, each with a distinct error.
- A TestOnly policy allowing loopback exists ONLY behind a Cargo feature named test-bind in racc-net. The feature is off by default, is enabled only by racc-testkit, and must never be enabled in a build of racc-host-agent or racc-app.
- Add scripts/check-features.sh and scripts/check-features.ps1: fail if the test-bind feature appears in the resolved features of racc-host-agent or racc-app (use cargo tree with feature output). Include a negative test: temporarily enable the feature on a dependency edge, confirm the check fails, revert. Wire both scripts into check-all.sh and check-all.ps1. (Today those binaries may not depend on racc-net at all; the check must still pass and must still be correct.)
- Add unit tests covering the full address table, including boundary addresses (100.63.255.255, 100.64.0.0, 100.127.255.255, 100.128.0.0).

D9. Real I/O shells (verified on loopback on this Windows PC).
- VideoSender: a UDP socket with SO_SNDBUF about 1 MiB sending to the viewer's address; owns a thread running the pacer and send queue.
- VideoReceiver: a UDP socket bound per bind policy, SO_RCVBUF about 2 MiB, one fixed 2048-byte receive buffer reused for every datagram, one thread feeding the reassembler and periodically calling poll(now) (at least every 5 ms using a read timeout), emitting events over a std channel with a bounded size. Accept datagrams only from the expected host IP address; others are counted and dropped.
- Clean shutdown: threads stop and join on drop or an explicit close within one second; no leaked threads after tests.
- Document that datagrams stay under the 1280-byte tunnel MTU by construction and that DF/PMTU probing is deferred.

D10. Impairment layer (racc-testkit).
- A deterministic simulated network operating on a virtual clock and a seeded PRNG, with configurable: independent loss probability, burst loss (a simple two-state Gilbert-Elliott model), reordering (probability and maximum displacement in packets), duplication probability, one-way delay with jitter distribution, and a bitrate/rate limit with a finite queue. Seeds make every test reproducible.
- A loopback UDP proxy that applies a (simplified) impairment profile to real sockets for the real-I/O tests. Keep real-socket tests tolerant (seeded, generous bounds) because real timing is noisy; put statistical assertions in the deterministic simulation tests.

TESTS (all required)
1. Slicer: fragment count and sizes for frame lengths 1, 1181, 1182, 1183, 2364, 2365, and the maximum 1024*1182; every datagram parses with racc-proto; reassembled bytes equal input; flags and LAST_FRAGMENT correct; frame lengths 0 and maximum+1 rejected.
2. Reassembler, unit: in-order delivery; each fragment order permutation for a 5-fragment frame; duplicates; one fragment missing; whole frame missing then next P-frame (must not be delivered) then keyframe (delivered); stale epoch; reset; inconsistent flags/ts/frag_cnt; wrong-size non-last fragment; late frame; frame_id wraparound; reorder within the window (delivered, no request) and beyond it (lost, request); timeout eviction; eviction when over the frame cap and over the byte budget.
3. Keyframe request policy: first request immediate; subsequent requests no closer than 200 ms; backoff doubles to the 1 s cap; resets after a keyframe is delivered; tested on the virtual clock.
4. Pacer: all datagrams within 60% of the interval for frames of 1 to 1024 fragments; even spacing within tolerance; behavior when frames arrive faster than they can be sent; queue overflow drops the oldest unstarted frame and raises ForceKeyframe; never abandons a frame mid-send.
5. Property tests (proptest): (a) for random frame sets, random loss/reorder/duplication, the reassembler never panics and every delivered frame is byte-identical to a sent frame; (b) delivered frame_ids strictly increase; (c) GAP SAFETY: a non-key frame is delivered only if every frame since the most recent delivered keyframe was also delivered, contiguous; (d) memory bound: current_inflight_bytes never exceeds the budget and in-flight frames never exceed 4, including under hostile input (random valid headers with random frame ids and frag_cnt up to 1024); (e) arbitrary byte vectors as datagrams never panic.
6. 8. Control connection over real loopback sockets: round-trip every one of the 16 ControlMessage types; oversize length prefix rejected without allocating the body; one-byte-at-a-time writes; peer closing mid-frame; read timeout; clean shutdown.

Real loopback video test: VideoSender to VideoReceiver through the loopback proxy: 0% loss delivers every one of 300 frames of varied sizes (including 1 byte, exact multiples of 1182, and a 233 KB keyframe) byte-identical and in order; with 2% seeded loss every delivered frame is byte-identical and ordered, drops are counted, and keyframe requests are emitted; no thread leaks.
