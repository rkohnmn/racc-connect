# Goal M9: macOS host and viewer (2015 Intel Mac)

Save as `docs/goals/M9.md`.

**Run after:** M8 complete (or at least M7; the clipboard part can follow).
**Run it from Codex on the Mac itself.** On the Windows PC the agent can only compile-check macOS code, so almost nothing would be verified. Clone the repository on the Mac, install Rust and Xcode command line tools, and launch the goal there. If you cannot, the prompt degrades to "write code, compile-check, and list human tests", which will need many rounds.
**Revisit before running:** confirm the Mac's exact model and macOS version (About This Mac, and `sw_vers`), update `docs/HARDWARE.md`, and make sure Tailscale works on the Mac. Read the `docs/IDENTITY.md` findings about the macOS Tailscale access method.

## Human checklist
1. Mac: macOS 12.3 or newer (Monterey 12.7.6 is reported), Xcode Command Line Tools installed (full Xcode only needed later for signing), Rust installed with the `x86_64-apple-darwin` target, Tailscale logged in, repository cloned, `cargo test --workspace` already passing on the Mac.
2. You will have to grant permissions in System Settings when prompted: Screen Recording, Accessibility. They are tied to the app's code signature, so expect re-prompts after rebuilds unless the binary is consistently signed (the goal provides an ad-hoc signing script).
3. Plug the Mac in and expect heat during performance tests.

## Launcher
```
/goal Complete the work specified in docs/goals/M9.md. Read AGENTS.md, docs/goals/COMMON.md, docs/DEV_SETUP.md and docs/PROGRESS.md first. Done only when every acceptance check in docs/goals/M9.md passes with evidence, then stop. Do not start the next goal.
```

## Prompt
~~~text
GOAL: M9. Make the 2015 Intel Mac a first-class host and viewer: ScreenCaptureKit capture (with a CGDisplayStream fallback), VideoToolbox H.264 hardware encode and decode, input injection with Accessibility, display topology, permission handling, clipboard, a LaunchAgent-based host agent, and the app's macOS rendering path. Verify it on the real machine.

COMMON.md applies in full, with these changes for this goal: the agent runs on the Mac (confirm with uname and sw_vers and record the model, macOS version, CPU and GPU in docs/HARDWARE.md; if the agent is NOT running on macOS, mark every behavior HUMAN-PENDING, implement the code and compile checks anyway and add the human tests). Windows-only checks in the base list that cannot run on macOS (for example the .ps1 script, the Windows target check) are run only if the tooling exists; otherwise record that the Windows PC must re-run them.

READ FIRST: AGENTS.md (sections 2.4, 7, 8), docs/CAPTURE.md, docs/ENCODE.md, docs/VIEWER.md, docs/INPUT.md, docs/HOST.md, docs/IDENTITY.md, docs/CLIPBOARD.md (if present), ADR 0001, docs/HARDWARE.md.

PREFLIGHT
Clean tree; scripts/check-all.sh green on macOS; cargo test --workspace passes on the Mac (portable crates). Record the environment. Confirm macOS version at least 12.3 (ScreenCaptureKit); if lower, the fallback path becomes primary and this is recorded.

DEPENDENCIES AND UNSAFE
Objective-C and framework bindings: prefer the objc2 family of crates (permissive licenses) and the core-graphics and core-foundation crates where they suffice; avoid unmaintained wrappers. Verify each crate's license and last release from the resolved metadata, record them in an ADR, and keep unsafe confined to crates/capture/src/macos/, crates/encode/src/macos/, crates/decode/src/macos/, crates/input/src/macos/, crates/clipboard/src/macos/ and the host agent's macos module, each with SAFETY comments and RAII wrappers (release every CF and ObjC object on all paths). Windows code must still compile out cleanly (no macOS crates in the Windows dependency tree and vice versa; check with cargo tree for both targets).

SCOPE

A. Capture (racc-capture macOS backend): enumerate displays with their identity via CoreGraphics (vendor, model, serial numbers from CGDisplay APIs), frame in global display coordinates, pixel size and point size, refresh rate, and the backing scale (keep the logical rectangle in points in HostDisplayGeometry per M3a; convert to the wire topology using physical pixels). Use ScreenCaptureKit: SCShareableContent for displays, SCContentFilter per display, SCStreamConfiguration with the NV12 (420v) pixel format at the stream resolution if the framework scales cheaply (otherwise capture at native size and scale on the GPU or via the encoder, measure and decide), minimum frame interval 1/30 s, a small queue depth (3), and do NOT show the cursor separately: let the cursor be baked into the video on macOS (document the trade-off: no cursor overlay for Mac hosts, the viewer must not draw a second cursor; send cursor datagrams with visible = 0). SCStreamOutput callbacks deliver IOSurface-backed CVPixelBuffers; hand them to the encoder without CPU copies. Handle stream errors, the display being removed or reconfigured (CGDisplayRegisterReconfigurationCallback), sleep and wake, and permission loss, mapping them to the same CaptureEvent set and recovery policy. Implement the CGDisplayStream fallback with the same trait, used only if ScreenCaptureKit is unavailable or fails to start (it is deprecated; record the behavior on this macOS version). Permission handling: check Screen Recording permission (the preflight API) and request it; when missing, emit a clear PermissionMissing status and event instead of black frames; provide a button-ready deep link to the right System Settings pane (document the URL or method that works on macOS 12).

B. Encode (racc-encode macOS backend): VTCompressionSession with H.264 Main profile, real-time mode, frame reordering disabled, a very long keyframe interval (keyframes on demand only), expected frame rate 30, average bitrate and data-rate limits sized to the tier, the low-latency rate control encoder specification if available on this macOS version (record whether it is), hardware encoder required and verified (report whether the session uses the Intel hardware encoder), forced keyframes via the per-frame property, and conversion of VideoToolbox's length-prefixed (AVCC) output to Annex B with SPS and PPS inserted before every IDR (has_config). Run the H.264 inspector from M5b over the output to prove no B-slices and correct parameter sets. Default tier for the Mac host is 720p30 (AGENTS.md section 2.4); the tier can be raised only by user setting after the performance test passes.

C. Decode and render (racc-decode macOS backend and the app's macOS render path): VTDecompressionSession from Annex B (convert to AVCC, build the format description from SPS and PPS, handle parameter set changes and resolution changes at IDR), output NV12 CVPixelBuffers uploaded to the wgpu Metal texture path through the toolkit chosen in ADR 0001 (CPU plane upload is acceptable; record cost). The same VideoSurface logic as Windows (letterbox, hold and atomic replace). Handle the Mac's lack of per-key physical code differences: macOS virtual key codes to HID usage mapping tables for capture (viewer on a Mac) and HID to macOS key codes for injection (host on a Mac), table-driven and tested like the Windows tables, including modifier and Command-key handling, and a documented rule for Command versus Windows-key forwarding between OSes (decide, record in an ADR; typical behavior: map physical keys, not meanings; offer a setting to swap Ctrl and Command for convenience).

D. Input injection (host): Quartz event services (CGEventCreateKeyboardEvent, CGEventCreateMouseEvent, scroll wheel events) posted to the HID or session event tap, absolute pointer positioning using the host's point rectangle for the selected display from M3a (macos points formula), relative motion, buttons, wheel, validation and rate limits identical to Windows, stuck-key release on session end, and permission handling: check Accessibility trust (the trusted-process check with the prompt option) and report PermissionMissing instead of failing silently. Ignore events when no authorized session is active.

E. Clipboard (macOS): NSPasteboard change count polling at a modest interval (about 250 ms) while a session is active (no notification API exists), text only, the same ClipboardSync core, loop prevention and limits as M8. No logging of contents.

F. Host agent on macOS: a LaunchAgent (user session) rather than a service. Provide a plist template and scripts/install-launchagent.sh and uninstall script for the human to run (the agent must not install them), supervision via launchd KeepAlive, the same HostRuntime, local IPC over a Unix domain socket in a user-private directory (mode 0600, owner checked), data directory under the user's Application Support folder, logging to a size-capped file. The host works only while the user is logged in (document: no login-window hosting on macOS). Sleep and wake and screen lock behavior documented and tested by the human.

G. Packaging groundwork (not final): an .app bundle layout script producing an ad-hoc signed bundle with the Info.plist keys needed for Screen Recording and Accessibility usage descriptions and a stable bundle identifier so permissions persist across rebuilds as far as possible. Full code signing, notarization and the DMG are M10 and require the human's Apple developer setup (record as HUMAN-PENDING).

MEASUREMENTS ON THE MAC (VERIFIED-RUN if the agent runs on the Mac; record method, date, machine, sample size; the human runs any step needing sudo, such as powermetrics)
- ScreenCaptureKit delivered frame rate and per-frame latency at native, 1080p, 720p and 480p targets; CPU time and private memory.
- VideoToolbox encode latency (p50, p95), output bitrate versus target, keyframe size and forced-keyframe response, at 480p, 720p and 1080p for 60 seconds with moving content; whether it kept 30 fps; dropped frames; CPU use; sustained temperature and throttling indicators (human-run powermetrics or the Activity Monitor reading; do not claim numbers you did not get).
- Decode and render cost on the Mac as a viewer at 720p and 1080p.
- A conclusion stating the highest tier the Mac sustains as a host at 30 fps without drops for 10 minutes, and its default.

TESTS
Portable tests continue to pass on the Mac; macOS mapping tables (key codes both directions); topology conversion with Retina and non-Retina examples including a secondary display with a negative origin; Annex B conversion and parameter-set tests with captured or synthesized AVCC samples; stuck-key and validation tests with a fake injector; clipboard core tests reused; real-system tests where possible: capture a real frame and check it is not blank, encode and inspect, decode a known stream and read back a frame checksum, post a harmless synthetic key event to the system only inside a controlled human-supervised step (HUMAN-PENDING; do not post events automatically).

DOCUMENTATION
docs/MACOS.md (permissions flow, capture and cursor decision, encoder settings and measurements, key mapping rules, LaunchAgent, limits and known issues, what differs from Windows). ADRs for the binding crates, the cursor-in-video decision, the Command/Ctrl rule, the LaunchAgent design. docs/HARDWARE.md human checks (HUMAN-PENDING): grant Screen Recording and Accessibility and watch the app react correctly when each is revoked and re-granted; sleep and wake the Mac while hosting; lock the screen; change displays and resolution; connect from a Windows PC to the Mac as host and verify video and control, and the reverse (Mac as viewer of a Windows host); key mapping with common shortcuts in both directions; corner and center pointer accuracy on the built-in display; a 10-minute sustained session with temperature and dropped frame notes; LaunchAgent install, start at login, kill and restart, uninstall. Update PROGRESS.md and OPEN_QUESTIONS.md.

HARD CONSTRAINTS
Do not install LaunchAgents, change privacy settings, run sudo or post input events automatically. Do not add audio, HDR, HEVC or AV1. Keep Windows builds unaffected (re-run the Windows target check or list it for the Windows PC). Do not commit captures. Do not start the next goal.

ACCEPTANCE CHECKS
B1 to B8 (B6 and B7 adapted as stated at the top), plus:
X1. On the Mac: real ScreenCaptureKit capture produces non-blank frames, the encoder output passes the inspector (no B-slices, SPS and PPS before every IDR), and the decoder round trip reproduces a frame (VERIFIED-RUN), or each is HUMAN-PENDING with exact steps if the agent was not on the Mac.
X2. Permission handling reports PermissionMissing for each missing permission (testable via the preflight APIs) without crashing.
X3. Key mapping tables tested both directions; injection validation and stuck-key tests pass with fakes.
X4. The measurement table and the sustained-tier conclusion exist with methods.
X5. Windows and macOS dependency trees are clean (no cross-platform binding crates leaking); both targets compile.
X6. docs/MACOS.md, ADRs, scripts and the human checklist exist.

FINAL REPORT: COMMON.md section 14, plus the Mac measurements, the sustained-tier conclusion and the list of permission and signing steps the human must do.
~~~
