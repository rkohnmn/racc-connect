Save as `docs/goals/M6.md`.

**Revisit before running:** read `docs/CAPTURE.md`, `docs/ENCODE.md` and `docs/IDENTITY.md`. If capture or encode findings change the pipeline (for example the iGPU/dGPU adapter story, or the fallback encoder), edit the "Pipeline" section below first. Confirm Tailscale works on PC #1 and PC #2.

## Human checklist
1. Working tree clean on `main`; Tailscale working on both Windows PCs.
2. The agent will NOT install the service. It provides `install` and `uninstall` scripts that **you** run in an elevated terminal. Expect to run the human checks on both PCs; they are the real test of this goal.
3. Keep a way to recover (another account or remote access) when testing lock, logoff and fast user switching.

## Prompt
~~~text
GOAL: M6. Build the Windows host: crates/host-agent (package racc-host-agent) as a service that supervises a helper process in the active console session; the helper owns the host runtime (listener on the Tailscale address, authorization, session, capture, encode, send). Add the platform-neutral HostRuntime to crates/core, a loopback host and a viewer-less probe client in racc-testkit, and a local IPC interface for the app. Input injection is NOT part of this goal (M7).

COMMON.md applies in full. Read AGENTS.md (sections 2.1, 2.2, 4.1, 8), docs/SESSION.md, docs/TRANSPORT.md, docs/CAPTURE.md, docs/ENCODE.md, docs/IDENTITY.md and docs/PROTOCOL.md first.

PREFLIGHT
Clean tree; check-all green; M2.6 (or its none decision), M3b, M5b and M5c complete. Read the human check results in docs/HARDWARE.md and note anything that affects the design.

DEPENDENCIES AND UNSAFE
windows crate features as needed (process, security, service, session APIs), the windows-service crate only if it keeps the service layer small and its license is permissive (record in an ADR; otherwise use the raw APIs), serde and serde_json for local IPC and settings (racc-core and racc-host-agent only). unsafe only in crates/host-agent/src/windows/ with SAFETY comments and RAII wrappers for tokens, handles and pipes.

PIPELINE (fixed unless the revisit note says otherwise)
Capture (M5a) -> encoder (M5b) on the same adapter -> HostSession actions (M3b) -> VideoSender (M2, with the recovery mechanism if M2.6 added one) over UDP to the viewer address from Hello; control over TCP (M2) on the Tailscale address and DEFAULT_CONTROL_PORT; authorization through racc-identity (whois plus allowlist).

DESIGN
1. racc-core::HostRuntime (platform-neutral, trait-based, testable with fakes): wires HostSession to a CaptureBackend, an Encoder factory, a VideoSender and a ControlConn using threads (std only; no async runtime) and bounded channels; executes session actions; feeds events back; enforces the memory and latest-wins rules; exposes status (listening address, waiting for Tailscale, viewer connected, current display, tier, encoder name, counts) and a pending-authorization queue. Behavior when Tailscale is down or has no address: status WaitingForTailscale, retry with backoff, no listening on any other address.
2. Windows modes of racc-host-agent (one binary, subcommands): 
   - `service`: the SCM service entry (auto-start, restart on failure). Supervises the helper.
   - `helper`: the host runtime in the console session.
   - `console`: run the helper logic in the foreground in the current session for development and for agent testing without installing anything.
   - `install` and `uninstall`: print or perform service registration; the agent must NOT run them. Provide scripts/install-service.ps1 and uninstall-service.ps1 for the human with clear comments, requiring an elevated shell, plus a `--dry-run` that prints what would happen.
3. Supervisor: a pure, sans-IO state machine (testable with fakes) deciding when to start, stop and restart the helper: inputs are console session changes (logon, logoff, lock, fast user switch), helper exit codes, service stop and ticks; outputs are StartHelper(session), StopHelper, backoff scheduling. Crash-loop protection (for example more than 5 failures in 60 s enters a cooldown and logs it). Unit-test heavily.
4. Helper launch (Windows module): determine the active console session, build a SYSTEM-derived token for that session, and launch the helper in it on the interactive window station and desktop. Research and document the exact approach used and its security implications. The helper must attach to the current input desktop when capture reports access lost (for example on UAC or the lock screen) so capture can follow the desktop: implement and document; if it cannot be made to work, document the limitation precisely and make the host report a clear "secure desktop not capturable" status instead of failing silently. All of this is HUMAN-PENDING for verification.
5. Local IPC for the app: a named pipe (Windows) with a security descriptor limited to the local interactive user and administrators and SYSTEM; length-prefixed JSON messages with bounded sizes: GetStatus, SetHostingEnabled, ListAllowlist, Approve, Reject, Remove, SubscribePending. Define the message types in racc-core (platform-neutral) and implement the server in the host and a client in racc-core for the app (M7 wires the UI). Tests with an in-memory transport.
6. Settings and state: hosting enabled flag, listening port, default tier, allowlist path. Stored under the machine-wide data directory the service can write (document the folder choice and permissions; the helper reads and writes as SYSTEM). No secrets.
7. Logging: tracing to a rotating file in the data directory (size-capped, a few files), plus the event log of the service for start, stop and failures; never log input, clipboard, frames or identities beyond a short label.
8. Probe client: racc-testkit gains a `racc-probe` binary: a viewer-less client that connects to a host address (uses ViewerSession from racc-session and racc-net), completes the handshake, receives video, writes the Annex B stream to an ignored folder, prints stats (frames, bytes, fps, loss, keyframe requests, RTT), and accepts simple stdin commands (list displays, switch N, pause, resume, quality N, quit). Also a `host-loopback` example in racc-testkit that runs HostRuntime with the test-bind feature on 127.0.0.1 so the whole pipeline can be exercised on this PC without Tailscale. Production binaries must still not enable test-bind (scripts/check-features).
9. Security checks: the listener rejects non-Tailscale bind addresses; connections from peers not on the allowlist get NotAuthorized and appear as pending approvals; whois failures reject; a second viewer gets Busy; control and video sources are filtered to the viewer address; resource limits (connection attempts per minute from a peer, slow-loris style stalls on handshake handled by HANDSHAKE_TIMEOUT_MS).

TESTS
Supervisor state machine tests; HostRuntime tests with fake capture, encoder and network; IPC protocol and bound tests; security tests for each rule in item 9; an end-to-end test on this PC: host-loopback plus racc-probe over 127.0.0.1 with the real DDA capture and a real hardware encoder for 30 seconds (VERIFIED-RUN: frames received, keyframes, no B-slices via the inspector, display switch to a second display and back, pause and resume, quality change, kill and restart of the helper while connected and the probe reconnecting). Report CPU time and private memory of the host process while streaming 720p30 and 1080p30, and idle (hosting enabled, no viewer).

DOCUMENTATION
docs/HOST.md: process model, supervisor diagram, helper launch and token details, IPC protocol, data directory layout, security rules, logs, install and uninstall procedures, known limits. docs/HARDWARE.md human checks (HUMAN-PENDING, with exact commands and expected results): install the service on PC #1 and PC #2 (elevated), verify it starts at boot with nobody logged on or after logon, connect racc-probe from the other PC over Tailscale and watch it stream, then lock the PC, unlock, sign out and in, fast user switch, UAC prompt on the host (does capture follow or report secure desktop), RDP or console session changes if used, kill the helper from Task Manager and confirm restart, uninstall cleanly. Update ADRs (service design, helper launch approach, local IPC, data directory), PROGRESS.md and OPEN_QUESTIONS.md.

HARD CONSTRAINTS
Never run install, uninstall or anything elevated. Do not add input injection, clipboard or UI work. Do not weaken the bind policy or allowlist. Do not leave the helper or service running. Do not start the next goal.

ACCEPTANCE CHECKS
B1 to B8, plus:
H1. Supervisor and HostRuntime unit tests pass, including crash-loop protection and restart-on-session-change.
H2. The loopback end-to-end test on this PC passes with real capture and a hardware encoder; numbers recorded.
H3. Security tests for every item-9 rule pass; scripts/check-features proves test-bind is absent from racc-host-agent.
H4. Local IPC tests pass including access-control documentation (verification of the pipe's ACL on real Windows is HUMAN-PENDING unless the agent can query the descriptor).
H5. install and uninstall scripts exist, are idempotent, support --dry-run, and have NOT been executed by the agent.
H6. docs/HOST.md and the human checklist exist.

FINAL REPORT: COMMON.md section 14, plus the loopback end-to-end results and resource measurements.
~~~
